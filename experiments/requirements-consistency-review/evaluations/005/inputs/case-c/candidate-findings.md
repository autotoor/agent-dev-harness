# Candidate Findings

## F-01: Loan Display And Overdue Badge

`requirements.md` -> Authority And Scope / Loan Contract and `owner-decisions.md` -> Promised Member Surface promise a loan view without selecting minimum visible information. The data includes status and due date, but their presence alone does not define display requirements.

The same candidate also asks whether to include a separate overdue badge and how to style it, referencing `requirements.md` -> Optional Presentation and `owner-decisions.md` -> Presentation And Deferred Capabilities. Decide both the minimum loan display and badge presentation before work proceeds.

## F-02: Waitlist

`requirements.md` -> Release Boundary And Work Sequence and `owner-decisions.md` -> Presentation And Deferred Capabilities defer waitlists. When a tool is unavailable, a waitlist could improve the lending experience. The reviewer recommends adding waitlist behavior before the member loan view is delivered.
