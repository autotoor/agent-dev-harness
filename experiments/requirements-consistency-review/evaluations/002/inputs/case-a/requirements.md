# Team Request Tracker Requirements

## Scope And Authority

These requirements and recorded owner decisions govern the first release. Workflow and model documents describe proposals, not running software.

## Request Coverage

Members can submit requests without due dates. Keep them visible in the active list during the applicable window, label the missing deadline, and never invent a date.

## Assignments

Requests may have multiple assignees. One shared request appears once in the team view and in each assignee's view; an update changes that request once.

## Aging And Review

Undated requests leave the active list after seven calendar dates including submission day. Requests needing approval appear in a separate pending-review queue. The first release only displays pending status; owner-facing resolution controls come later.

## Acceptance Criteria

An undated request is accepted, labeled without a deadline, and visible in the active list during its seven-day window. Two assignees see the same request, without duplicating it in the team view.

## Deferred And Open

Calendar export is deferred. Retention after team deletion is acknowledged as open and must be decided before production deployment. Implementation framework and database selection are open.
